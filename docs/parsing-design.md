# 智能解析系统：设计（待做）

把别人的东西——论文里的框架描述、开源项目的源码和配置、一份提示词、一段运行日志——读成我们的语义：编排文档（`hub/cases/<案例>/*.md`）和事实（`traces/`）。现在这件事靠一次性的导入脚本（`hub/tools/_reference/import_*.js`）和按数据集手写的读取器完成，质量参差，只能当参考。这份文档说如何做成一个专门的、可验证的系统。**还没有实现。**

## 1. 要解决的真实问题

`hub/tools/check_shells.js` 把 1141 个案例的解析结果逐个画一遍，第一次跑就抓到的问题，是这个系统要系统地避免的：

| 现象 | 根因 |
|---|---|
| 一个分组里写了没定义的成员，整个案例画不出来 | 引用没有校验：id 写错、带空格、大小写不一致 |
| 阶段没有任何步骤和执行者，画成空框 | 抽取出了结构，没抽出内容 |
| 同一个人列在两个分组里 | 抽取没有“归属唯一”的约束 |
| 角色说明是整段提示词原文 | 没有区分“一句话职责”和“原始材料” |

共同点：抽取阶段只管“像不像”，没有一道独立的、机械的“对不对”。

## 2. 原则

1. **输出就是我们的格式。** 产物是 md 编排文档或 hub-graph JSON，人能读、能改、能 diff，页面零改动。不为模型另造一套中间概念。
2. **大模型提议，机械检查裁决。** 模型负责读懂；是不是合格，由解析器和检查脚本判断，不由模型自评。
3. **每一条都带回指。** 个体、线、关卡、文档都写 `evidence:`，指向来源的文件和行（或片段哈希）；验证器检查这个片段真的在原文里，并且和断言相容。没有回指的条目标为“推断”，页面按“未声明”的口径画。
4. **结果是参考，不是真源。** 产物放进 `hub/cases/_reference/<来源>/`，页面里折叠、检查默认不进；人修订过的才移出来。
5. **本地、可重放、省钱。** 输入按内容哈希缓存，同样的输入同样的输出；密钥由使用者自己带，会话内容不发给任何不是使用者指定的服务，进模型前先过 `maskSecrets`。

## 3. 流水线

```text
来源适配 → 切片 → 抽取（模型）→ 规范化 → 验证 → 修复回路 → 落盘 + 报告
```

- **来源适配**：把一种来源变成“带位置的文本块”：`{source, path, lines, text}`。源码、README、配置、日志各一个适配器，沿用 `SourceAdapter` 的纯函数风格，不碰网络。
- **切片**：按语义切（一个文件、一个 agent 定义、一次对话轮），每片控制在模型窗口的一小部分，片间用符号表（已知个体 id 清单）连接，而不是把全文塞进去。
- **抽取**：提示词里给目标语法（`docs/hub-graph-format.md` 的 md 协议）、两三个满分示例、符号表；要求只输出该语法。一次只抽一类对象（个体 → 分组 → 关系 → 流程 → 文档），后一类可以引用前一类的 id。
- **规范化**：id 小写、ASCII、无空格；同名合并；一人一个直属分组；`role` 截成一句，原文进 `*_file` 附件。
- **验证**（全部是现成的或很小的）：
  1. `from-docs` 解析通过，没有未知字段被丢弃；
  2. 引用完整：成员、`watches`、关卡 `decider`、阶段 `executors` 都指向已定义的个体；
  3. `check_shells.js`：没有空框、没有无名卡、没有破文字；
  4. 回指检查：每个 `evidence` 片段在原文里，且包含该条目的关键词；
  5. 覆盖：来源里出现的角色名，有多少成了个体（漏抽的告警）。
- **修复回路**：验证错误按条目收集，连同原文片段和上一版产物发回模型，最多三轮；三轮后仍不合格的条目降级为 `#status/unverified` 留在文档里，不删。
- **落盘 + 报告**：写文档，同时写一份机器可读的报告（每个案例的通过项、降级项、被丢弃项），由 `check_shells.js --all` 汇总成覆盖表。

## 4. 评估

- **金标集**：挑 20–30 个来源，人写一份满意的编排，作为回归基准；指标是个体召回/精度、关系召回/精度、流程步骤召回，以及“验证全过”的比例。
- **覆盖表**：沿用 `check_shells.js --all` 的表（空框、无头像、破文字、悬空节点），每次改提示词或换模型都对比。
- **漂移**：同一来源重跑，产物应该稳定；diff 超过阈值要人看。

## 5. 放哪里

独立的可选包 `parse/`（命令行工具），**页面不依赖它**：

```bash
hub-parse <来源> --out hub/cases/_reference/<名字>     # 解析一个来源
hub-parse --check hub/cases/_reference/<名字>          # 只验证已有产物
```

它复用 `hub/js/sources/from-docs.js`（在 node 里用 `hub/tools/load.js` 的方式加载）做验证，所以“能不能被页面读懂”和“验证是否通过”是同一件事。读取器（`HUB.fromTraces.readers`）负责事实，不在这个系统里：事实应该由原始数据集的读取器按确定性规则读出，不交给模型。

## 6. 里程碑

1. **验证器独立出来**：把 2 的引用检查和回指检查做成 `check_refs.js`，先用在现有的 1141 个案例上，给出一份“哪些是模型写错的”清单。
2. **一个来源做通**：选一个形态最规整的来源（某个开源框架的 agent 定义文件），走完整条流水线，对着金标集量指标。
3. **修复回路和缓存**。
4. **第二、第三个来源**，抽出共同的适配器接口。
5. **日志类来源**：交给 `trace/` 的适配器先读成契约，再由本系统从契约生成“补写的编排”。
