# Agent Architecture Hub

**多智能体协作观察台：把编排写成文档，与实际发生的事对照。**

[English](README.md) | 简体中文

Hub 把三类输入解析成同一个统一模型——写下来的编排（Markdown 文档或 JSON）、记录下来的运行、以及你本机上真实的智能体会话——再用一组相互联动的观察面板呈现。模型把三层分开保存：**定义**（协作被写成什么样）、**事实**（实际发生了什么）、以及由两者算出的**分析**。页面就是调试这两者差异的工具。

![由五份 Markdown 文档解析出的团队：部门、个体和四类线](docs/img/overview.jpg)

## 自动解析

输入靠识别，不靠登记。把文件夹或文件放进 `hub/cases/`，目录就会发现它；由识别器判断它是什么，再由加载这一类的来源把它变成模型。

| 输入 | 识别方式 | 解析成 |
|---|---|---|
| 编排文档（Markdown） | 含 `meta.md` 的文件夹 | 个体、分组、关系（任务线、信息线、监督线、渠道线）、能力渠道、带受众的文档、流程（阶段、步骤、带出口的判断点）、场景和决策记录。个体可以标注它跑成的本机会话（`session: codex:…`），详情里就能打开那个会话的 Trace |
| hub-graph（JSON） | 符合 [hub-graph 格式](docs/hub-graph-format.md) 的 `.json` 文件 | 同一个模型；不认识的对象类型降级成默认卡片，不会报错 |
| 记录的轨迹 | `traces/` 文件夹，由和案例 `meta.md` 里 `source:` 对得上的读取器读取 | 替换掉模拟值的事实：运行、发言记录、带依据的交接（记录里明写，或由来源协议推出）、结局和失误标注 |
| 本机智能体会话 | Codex、Claude Code、OpenCode、Gemini CLI、Factory、ZCode 的日志文件，每种格式一个适配器 | 同一份会话契约；一个会话连同它的子智能体变成个体、一次派出的子智能体组成的分组、派发与交付线，以及模型渠道和工具渠道。会话背后没有写下来的定义，定义是从事实里读出来的；也还没有决策层：会话的一次运行按记录下来的轮和步骤打开 |
| 内置示例团队 | `hub/data/base.js` 里的 62 个团队 | 定义加上模拟的事实，出现的每个地方都标明“模拟” |

解析的行为方式和它接受什么同样重要：

- **只解析出一部分，就画到解析出的那一部分。** 页面不认识的字段原样保留，在对象详情的“原始字段”里列出；不会静默丢弃。
- **事实不靠相邻关系推断。** 交接只在记录里写明或来源协议推出时才存在；发言的先后保存为记录，不会被连成线。没人记录的量写“未采集”，不写 0。
- **残缺的结构不画成空壳。** 分组里写了未定义的成员，就画没有他的分组；没有任何成员的框不画；没有步骤的阶段保持为一张卡。
- **解析质量按规模检查。** `hub/tools/check_shells.js` 逐案例构建场景，统计空框、没有名字或头像的卡、破损文字和没有连线的节点；它覆盖随仓库提供的案例，加 `--all` 还覆盖作者语料里 1141 个机器整理的案例。
- **机器整理的案例收在架子里。** 由论文和数据集整理出的案例放在 `hub/cases/_reference/`，界面里默认折叠，默认检查不进入。

## 观察面板

一个观察状态——案例、主体、粒度、聚焦、时间切面、对照方式、线、选中对象——驱动所有面板，并同步到地址栏，所以一个链接就能还原屏幕上的全部内容。

### 画布

图形呈现一次画一个主体。视图是观察状态的预设：切换只改一两项，元素原地移动。

| 视图 | 主体 | 回答的问题 |
|---|---|---|
| ① 完整协作图 | 组织，个体粒度 | 所有个体和它们之间的线 |
| ② 部门架构图 | 组织，部门粒度 | 组织怎么划分；线合并并标注次数 |
| ③ 单案例路由图 | 组织，聚焦一个案例实例 | 一件工作实际用到了哪些个体和交接；其余变淡 |
| ④ 业务流程图 | 流程 | 阶段、判断点、谁来判断、在哪里打回或上报给人 |
| 协作轨迹图 | 协作 | 一条记录一条记录地看谁把什么交给了谁，可回放；只画记录能支撑的部分 |
| 运行明细 | 执行 | 一次运行画成由轮、步骤和调用组成的树，附输入和输出（内嵌的 Trace 视图）；决策记录——备选、选择、理由——在案例文档或模拟器提供时显示 |

线分四类：任务线、信息线、监督线、渠道线。与事实对照时，实线是写了也用了，虚线是写了没用过，橙色是发生了但没写。对照方式在“定义 / 对照 / 事实”之间切换；粒度从部门到小组到个体（流程是阶段和步骤，执行是决策和调用）。卡片和部门框可以拖动，挪动量按案例记在浏览器里，一个按钮即可还原。

### 侧栏与详情

| 面板 | 内容 |
|---|---|
| **预设** | 62 个内置示例团队，按规模分层，带分类筛选和搜索 |
| **目录** | `hub/cases/` 下发现的案例，按它们所在的文件夹分层；收起的文件夹点开才读取 |
| **结构** | 定义的树：个体与分组、能力渠道、流程、带受众的文档、案例实例 |
| **体检** | 需要人处理的事（拍板、上报、调整方向），以及架构检查的发现：从没被派出过的个体、从没用过的线、没有任何文档声明的交接、没送达的文档、返工回环、排队、故障渠道 |
| **会话** | 本机上发现的智能体会话及其实时状态；带子智能体的会话可画成协作图；链接到 Trace 查看器的来源与项目总览、统计和检索 |
| **详情**（右栏） | 案例概况，或选中的对象：个体、分组、关系、能力渠道、阶段、步骤、判断点、案例实例、运行、轨迹中的一条记录。每个对象显示职责、触发、监督、文档、渠道、运行和原始字段，以及可对它做的操作：对话、插话、催办或改派、补送文档、把规则修改交给中枢智能体、暂停或恢复渠道、放行判断点。每个操作都会记成一条事实，分析随之重新计算 |

### 面板呈现、时间轴与控件

- **面板呈现。** 同一个状态不画图，改用九个面板呈现：系统总览、需要人处理的事、个体名册（状态、工作量、信息完整度，可排序可搜索）、任务与信息、送达情况、能力渠道、架构体检、按分组/步骤/判断点汇总的运行统计、维护情况。
- **时间。** 底部时间轴显示案例实例和事件随时间的分布。移动切面，所有面板按那一刻重新计算；回放让切面自行推进。
- **控件。** 视图按钮，快捷键 `1`–`4` 和 `T`；粒度、对照方式和呈现方式开关；线和叠加层开关；我的视图；沿观察历史后退与前进（`Alt` + 方向键）；`?` 打开图例和键盘表。
- **Trace 查看器（`/trace/`）。** 面向全部会话的独立视图：可筛选的列表、调用树、对每一步的全文检索、统计，以及按来源和项目的总览。

## 快速开始

需要 Node.js 24 或更新。

```bash
npm run setup     # 只做一次：安装依赖并构建 Trace 查看器
npm start         # 观察台在 http://127.0.0.1:8899/
```

Windows 下 `start.bat` 两步都做并打开浏览器。`npm start -- --port 9000` 换端口；默认端口被别的程序占用时，自动使用下一个空闲端口并打印出来。

页面、会话接口和 Trace 查看器由同一个进程提供，应当一起使用。页面的案例都从这个服务读取，连不上时会直接说明；它不打算从磁盘或静态托管打开。

## 编写案例

案例是 `hub/cases/` 下含 `meta.md` 的文件夹。

```text
hub/cases/demo_minimal/
  meta.md      标题和简短说明
  agents.md    团队里有谁
  groups.md    怎么分组
  process.md   阶段和判断点
  relations.md、docs.md、scenarios.md、decisions/<智能体>.md    （均可选）
```

最小示例的 `agents.md`：

```markdown
---
hub: "1.0"
kind: agents
case: demo_minimal
---

# @worker [individual] #phase/build #role/engineer #hub
name: 执行者
model: claude-sonnet-5-5
role: 按清单把活干完并交付
trigger: 分派任务后启动

# @checker [individual] #phase/qa #role/reviewer
name: 把关者
role: 检查交付是否符合清单，不合格打回
watches: [worker]
```

`# @id [type] #tag` 开一个对象，`key: value` 行和列表描述它，标签写成 `命名空间/值`。协议及其 JSON 形式见 [docs/hub-graph-format.md](docs/hub-graph-format.md)。

## 扩展

每个接缝都是一张登记表，新增一类输入或输出就是一次登记：

| 想加 | 登记 |
|---|---|
| 一类磁盘上的案例 | 一个识别器（`HUB.catalog.recognize`）和一个来源（`HUB.model.addSource`） |
| 一种事实来源 | 一个提供者（`HUB.facts.register`） |
| 一个数据集的记录 | `HUB.fromTraces.readers` 里的一个读取器，按案例的 `source:` 匹配 |
| 一个视图 | `HUB.views.register` |
| 画板能画的主体，或自带的一层 | `HUB.render.register` |
| 一种智能体会话日志 | `trace/packages/adapters` 里的一个 `SourceAdapter` |

[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)（英文）说明各部分及其配合。[docs/parsing-design.md](docs/parsing-design.md) 是大模型辅助、带机器验证的解析系统的设计（尚未实现）。

## 安全与隐私

- 服务只监听 `127.0.0.1`，拒绝 `Host` 不是自身地址的请求（防 DNS 重绑定）。不发送任何 CORS 头，所以浏览器里的其他网站读不到你的会话。
- 只读：只有 `GET` 和 `HEAD`，静态文件限定在各自目录内，路径穿越一律拒绝（编码两次也不行）。
- 会话在本机解析；索引缓存在 `~/.agent-hub/trace`（用 `HUB_TRACE_HOME` 改位置）。工具输入输出里形似密钥的字符串在解析时打码。
- 页面带内容安全策略（`self`，字体另允许 Google Fonts）。没有网络时回退到系统字体。

## 仓库结构

```text
index.html          页面
hub/
  js/core/          模型：状态、分析、视图、目录、事实提供者
  js/sources/       解析：案例文档、hub-graph、记录的轨迹、会话、模拟器
  js/shell/         画布外面的页面：镜头、标签页、主题
  js/obs/           画布和面板：场景、卡片、控件、侧栏页
  css/、data/       样式；内置的智能体、示例团队和文本
  cases/            案例（参考语料在场时位于 cases/_reference/）
  tools/            在 node 里不开浏览器把整个模型跑一遍的检查
  vendor/           Trace 视图的单文件构建产物（来自 trace/apps/viewer）
trace/              会话工作区：契约、适配器、OpenTelemetry 导出、服务、Trace 查看器
concept/            概念画板：独立的拖拽式团队设计器，自带数据，位于 /concept/
docs/               架构、格式、设计
```

`npm test` 运行节点检查和工作区测试；`npm run typecheck` 检查 TypeScript。

## 概念画板

`/concept/` 是这个项目当初长出来的手工团队画板：自包含的页面，通过拖拽组合智能体团队，带自己的智能体和团队目录。它是中文版页面，保持原样，与观察台分开；数据不共用。
