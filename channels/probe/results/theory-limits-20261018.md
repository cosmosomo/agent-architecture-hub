## 二、8 个能力单元的立体认知与理论上限系统推导

### 1. `native-meta` 读原生会话元数据
- **所在尺度**：**一个会话**。
- **那一级循环谁持有**：各产品本地持久化存储（本地 SQLite、JSON/JSONL 数据库与文件元数据系统）。
- **外面能进去的时机和通道**：
  - 时机：冷旁路读取，随时可读，不依赖会话是否在跑。
  - 通道：本地文件系统与只读数据库连接（如 Codex `~/.codex/sessions/*.jsonl`、Antigravity `conversation_summaries.db`、Claude `~/.claude/projects/`、ZCode `db.sqlite`、Hermes `state.db`）。
- **理论上限**：读取并结构化解析各产品本地持久化存储里记录的所有非加密元数据（原生标题、首尾时间戳、模型名称、token 累计用量、工具统计、置顶标记、归档状态）。
- **根本限制**：平台若未将字段落盘（仅保留在内存活跃运行时中），外部通过冷文件无法读取；专有二进制加密格式若无密钥或私有协议则无法解密。
- **原生做不到时最多补齐到**：**中心会话台账与缓存层**。中心在首次扫描或经网关初次交互时建立该会话的元数据镜像（据首轮用户输入推测标题、据已落盘转录推算时间与 turn 统计）。
- **补齐代价**：中心需要维持额外的元数据缓存；对原生桌面端在外部独立修改（如人在原生界面重命名）存在轮询延迟。
- **已有黑板实测支撑**：
  - Antigravity：读取 `conversation_summaries.db` 提取顶层 132 个原生会话标题与时间戳（黑板 L0/L2 行）。
  - Codex：读取 `threads.json` 提取 1157 条索引与元数据。
  - 8899 后端：`GET /api/sessions?slim=1` 与 `/api/sessions/<id>` 实时返回 `stats.turns`、`stats.toolCalls`、`startedAt`、`updatedAt`。

### 2. `content-search` 全文检索
- **所在尺度**：**一群会话**。
- **那一级循环谁持有**：**中心（我们自己的服务）**。各产品自身最多在各自桌面端提供单会话内关键词定位，跨产品、跨会话的检索循环天然不属于任何单一产品，必须由中心作为宿主持有。
- **外面能进去的时机和通道**：
  - 时机：各产品会话轮次结束落盘之后。
  - 通道：中心后台扫描管道读取磁盘文件，构建本地倒排索引（`trace/apps/cli/src/search.ts` / SQLite FTS5 / MiniSearch），通过 `GET /api/search` 暴露。
- **理论上限**：毫秒级跨全部产品的历史会话（覆盖所有轮次的 user/assistant 输入输出、模型思考过程、工具调用参数与返回结果）执行关键词匹配或语义切片检索。
- **根本限制**：未落盘的流式中间态搜不到；云端未同步到本地的会话搜不到。
- **原生做不到时最多补齐到**：**中心统一索引构建**。中心统一定期增量扫描全盘会话存储并建立检索倒排表。
- **补齐代价**：构建索引消耗本地磁盘空间与后台算力；会话刚写入时与索引更新之间存在微小的时间窗口延迟。
- **已有黑板实测支撑**：
  - L2 接口实测：`GET /api/search?q=...` 与 `GET /api/stats`（支持跨 1500+ 会话检索消息正文并返回分词与上下文片段）。

### 3. `context-usage` 上下文占用
- **所在尺度**：**一轮之内 / 一个会话**。
- **那一级循环谁持有**：原生模型调用循环（各产品客户端组装 prompt 并调用供应商 API 的网络收发层）。
- **外面能进去的时机和通道**：
  - 时机：每次 LLM API 响应返回时（单步完成点）。
  - 通道：供应商响应头或响应体中的 `usage` 字段（`prompt_tokens`, `completion_tokens`, `total_tokens`），或 ACP 协议事件 `session/update`，以及会话落盘日志中的 tokens 字段。
- **理论上限**：每一步/每一轮结束后精确掌握当前会话在模型上下文窗口中的实际占用量、最大窗口硬限制、剩余比例及溢出预警。
- **根本限制**：部分本地模型或中转服务不透传 `usage` 统计；在一轮进行中流式吐字阶段无法提前预知本次最终消耗总量。
- **原生做不到时最多补齐到**：**中心离线 Tokenizer 估算**。中心按该模型对应的分词器（如 cl100k_base、tiktoken、o200k）对该会话当前全部历史上下文与系统提示词进行本地离线计算。
- **补齐代价**：本地分词需消耗后台 CPU；与云端供应商私有模板包装、特殊隐藏 token 存在 1%~5% 的估算误差。
- **已有黑板实测支撑**：
  - Codex：`rollout.jsonl` 每轮显式记录 `token_count` 与 `cumulative_tokens`。
  - Claude：stream-json 的 `message_delta` 返回真实 `usage`。
  - 8899 会话契约：`stats.records` 统计字段。

### 4. `reasoning-effort` 推理力度
- **所在尺度**：**一轮之内 / 一个会话**。
- **那一级循环谁持有**：原生请求组装层（各产品构造发给供应商 payload 的位置）。
- **外面能进去的时机和通道**：
  - 时机：一轮开始前的请求参数构造点。
  - 通道：命令行参数（`--reasoning-effort`）、ACP 请求体参数（`reasoningEffort: "low"|"medium"|"high"`）、或供应商专有字段（如 `reasoning_effort`、Anthropic `thinking: { budget_tokens: N }`）。
- **理论上限**：新建会话或在发起新一轮请求时，按需精确指定当前轮的思考 token 预算或推理强度级别（low / medium / high）。
- **根本限制**：非推理类模型架构（如普通 Haiku/Flash）本身不支持；部分客户端将推理力度固定写死在代码内，不开放外部参数控制。
- **原生做不到时最多补齐到**：**渠道映射子模型 / 系统提示词注入**。通过渠道后缀指定特定变体（如 `o3-mini-high`），或在第一轮/新一轮的系统提示词中注入强约束（“请开展深入长链思考，逐步推导...”）。
- **补齐代价**：提示词引导不如模型级 API 严格可控，且会占用有限的上下文窗口与输出预算。
- **已有黑板实测支撑**：
  - Codex app-server：配置中支持指定 `reasoning` 选项。
  - GLM-5.3-Flash：通过 `coding-plan` 档位切换实现长链思考规划。

### 5. `list-projects` 列项目
- **所在尺度**：**一群会话**。
- **那一级循环谁持有**：**中心（我们自己的服务）**。各家产品仅知晓自己当前打开的工作区（如 Antigravity `workspaces.json`、Claude `projects` 目录），跨产品、跨生态的项目汇聚必须由中心持有。
- **外面能进去的时机和通道**：
  - 时机：会话目录扫描与聚合点（只读冷旁路）。
  - 通道：中心扫描各产品会话记录中的 `cwd`、Git 根目录与配置目录，经 `normalizeWinPath` 路径归一算法聚类。
- **理论上限**：实时完整呈现本机被所有智能体关联过的代码仓库与工程根目录清单，精确关联并归集各项目下的所有会话、活跃状态与产出物。
- **根本限制**：临时无盘运行、或会话未记录有效 `cwd` 的空悬会话无法自动归入项目。
- **原生做不到时最多补齐到**：**中心跨产品项目注册表**。中心全盘扫描所有会话的 working directory 并向上追溯 `.git` 边界，建立统一项目字典（`nativeProject` 映射）。
- **补齐代价**：多路径深度遍历与 Git 根检测有一过性 I/O 开销，需依赖中心缓存。
- **已有黑板实测支撑**：
  - L2 接口实测：`GET /api/sessions?slim=1`，已将 9 家产品的 1500+ 会话按归一化项目路径（如 `E:/program/GIT/Agent/multi/Agent-Architecture-Hub`）成功归集（黑板第 1758 行、第 1940+ 行实测 pass）。

### 6. `workspace-files` 列工作区文件
- **所在尺度**：**一个会话 / 底座**。
- **那一级循环谁持有**：本地文件系统与宿主工作区。
- **外面能进去的时机和通道**：
  - 时机：随时通过宿主只读文件接口或会话挂接的工具。
  - 通道：宿主文件系统 API（`fs.readdir`、`git ls-files`）或智能体自身的目录遍历工具。
- **理论上限**：完整、高效获取指定会话或项目工作目录下的文件树与结构，支持 `.gitignore` 过滤，并在受控安全沙箱内提供文件清单。
- **根本限制**：在远程无盘容器内运行且未挂载本地卷的工作区，外部宿主无法直接通过操作系统文件系统枚举。
- **原生做不到时最多补齐到**：**中心安全文件代理 / 智能体工具代理**。中心提供带安全边界与深度限制的目录只读枚举接口，或派发指令调用智能体内的 `list_directory` 工具。
- **补齐代价**：超大工程目录递归遍历消耗磁盘 I/O；必须严格设立目录白名单以防路径遍历攻击（Directory Traversal）。
- **已有黑板实测支撑**：
  - L2 接口实测：`GET /api/sessions/<id>/files` 能够精确提取会话读写及提到的文件（实测 9 家产品均返回 HTTP 200）。

### 7. `native-meta-write` 写回原生元数据
- **所在尺度**：**一个会话**。
- **那一级循环谁持有**：原生会话持久化层（各产品的本地 SQLite / JSON 文件存储）。
- **外面能进去的时机和通道**：
  - 时机：会话非独占运行的静止状态（`unclaimed` 或 `hub-idle`）。
  - 通道：原生 CLI/API 修改接口（如 Codex `thread/name/set`），或直接修改本地 SQLite 数据库表 / JSONL 文件。
- **理论上限**：外部对会话的改名、标签、置顶、归档等修改，能够直接持久化落盘至各产品自身存储，原生桌面应用重新聚焦或刷新时原生同步显示修改结果。
- **根本限制**：原生桌面端持有常驻独占文件锁，或在内存中持有非响应式缓存且不监听文件系统变更时，外部写入会被原生应用覆盖或直到应用完全重启才可见。
- **原生做不到时最多补齐到**：**中心别名与覆盖注册表**。中心在自己的会话元数据层（如 `server.ts` 中的 `bindings` / `titles` 映射）维护用户自定义别名与标签，优先向网页和网关呈现。
- **补齐代价**：中心别名仅在中心界面生效，原生客户端窗口内依然显示原旧名称。
- **已有黑板实测支撑**：
  - Codex：经 app-server 执行 `thread/name/set` 成功就地修改原生线程名称（L0/L2 实测 pass）。
  - Antigravity：通过 SQLite 直接改写 `conversation_summaries.db` 记录。

### 8. `app-sync` 原生应用同步可见
- **所在尺度**：**一个会话**。
- **那一级循环谁持有**：原生桌面应用进程（其主线程事件循环与 UI 渲染管道）。
- **外面能进去的时机和通道**：
  - 时机：外部发话推进或完成时。
  - 通道：桌面端与其底层引擎通信的统一 IPC/RPC 协议通道（如 Codex 桌面端直接与 app-server 双向同步；Antigravity 经 `language_server` agentapi 推进）；或客户端对本地文件系统的热重载（File Watcher）。
- **理论上限**：外部（中心网页或命令行网关）触发的每一轮发话、工具步与最终回复，在原生桌面端窗口中实时、无闪烁呈现，如同在桌面端直接键入。
- **根本限制**：桌面客户端被设计为单实例独占孤岛且不监听外部存储变化（如部分客户端仅在启动时读一次数据库）时，外部推进在桌面端无法自发实时渲染。
- **原生做不到时最多补齐到**：**切换触发就地重载 / CDP 聚焦激活**。人在桌面端通过切换至其他会话再切回触发就地重载；或由中心通过 OpenCLI/CDP 向桌面端发送前台重聚焦刷新信号。
- **补齐代价**：需操作前台窗口，可能与用户正在进行的本地鼠标键盘输入产生焦点抢占。
- **已有黑板实测支撑**：
  - Codex：常驻驱动下外部 `turn/start` 推进，Codex 桌面端当前会话实时同步更新（L0/L2 实测 pass）。
  - Antigravity：经 `agentapi send-message` 外部推进，桌面端 Cascade 界面同步追加渲染。

```markdown
| 写回原生元数据 | 外部修改（重命名标题、打标签、置顶、归档）能够直接持久化写入各产品自己的原生存储，桌面应用刷新/重聚焦时原生同步可见 | 原生 CLI/API 修改接口（如 Codex thread/name/set），或在会话静止非独占时的本地 SQLite/JSON 写入 | 原生应用持有独占文件锁、或仅在内存中缓存状态且不监听文件变更时，外部写入会被原生应用覆盖或需重启桌面端 | 中心在自己的会话元数据注册表（如 server.ts bindings / titles）中覆盖别名与标签，优先向网页和网关呈现 | 中心别名仅在中心界面生效，原生桌面端界面内依然显示原旧名称 |
| 原生应用同步可见 | 外部（中心/网页/命令行）发起的每一轮消息推进与工具产出，在原生桌面端应用窗口中实时、无闪烁同步渲染呈现 | 各产品桌面端与其底层引擎通信的统一 IPC/RPC 协议通道（如 Codex app-server，Antigravity agentapi） | 桌面客户端被设计为独立运行、独占会话且不热重载本地存储（只在启动时加载）时，外部推进在桌面端无法实时反映 | 人在桌面端通过切换会话/重选列表触发就地重载，或由中心借助 CDP/OpenCLI 向桌面端发送重聚焦刷新信号 | 需操作或依赖桌面端前台窗口，可能与用户当前交互产生焦点冲突 |
```
