# 问各家：你有什么独家生态（10-19）

## 用户的原话

> “其实每家生态都可以问一问他们有没有这些功能，比如其实有些生态他们的那个 Computer Use 会做的很好，豆包的 Computer Use 就做的很好。”
>
> “其实不需要太多，就是问对方有什么独家生态，然后写到面板里或者自己主动注册功能，就这样。独家功能和闭源程度分析什么的”

## 要回答的问题

你这家产品（你运行在其中的那个应用或命令行），有哪些独家的功能或生态？独家指别家没有，或者你们做得特别好。比如操作电脑、浏览器、内置的多智能体、定时任务、长期记忆、插件或技能市场、云端运行。这些功能各自开放到什么程度：开源、有公开接口、只能在界面里用、还是不开放？

## 先查网上

用户 10-19 原话：“一定要记得，所有原生的生态的研究都要辅助网络调研来研究，不能闭门造车。因为很有可能开源的项目就已经做了这个功能了。也很有可能有社区讨论这个东西这些原生的生态，各家的产品都是很多很多人用的，所以一定有人研究。”

动手摸本机之前，先查：开源项目（GitHub 上有没有人做过同样的接入、自动化、逆向）、官方文档和更新日志、社区讨论（issue、论坛、博客、视频）。报告里带链接，写清借鉴了什么、哪些和本机实测对不上。搜索工具：`node hub/tools/search_hub.js search "<词>" --max 5`（可加 `--domains github.com`），正文提取：`node hub/tools/search_hub.js extract "<链接>"`；你自己的搜索工具也可以用。

## 怎样算做成

- 每样功能用命令自己登记一条（产品 id 在派活单里）：

  ```
  node hub/tools/agent_gateway.js feature --agent <产品 id> --name <功能名> --what <做什么> --entry <入口>
       --exclusive 独家|别家也有|不确定 --openness 开源|公开接口|只能界面|不开放 --evidence 试过|看到|推测 [--note <说明>]
  ```

  依据要如实写：试过（当场试了，在 note 里写命令和结果）、看到（工具列表、文档、设置里看到）、推测。
- 每条加 `--how <实现路径>`：它是怎么做到的。例如浏览器自动化，是走浏览器调试接口（CDP）、视觉识别（截图）、DOM 解析、无障碍树，还是系统级鼠标键盘。
- 知道成本、性能或别的特点的，再补一条注释：`node hub/tools/agent_gateway.js note --agent <产品 id> --on <功能名> [--cost <成本>] [--perf <性能>] [--tags 词,词] [--text <说明>] --evidence 试过|看到|推测`。
- 交回一句话：登记了几条，其中独家几条，各开放程度分别几条。

## 不能碰的

不改代码和全局配置，不对用户正在用的会话发消息，不写明文密钥。
